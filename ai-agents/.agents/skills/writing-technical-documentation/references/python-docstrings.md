# Python docstring

Используй для создания, содержательной правки и проверки Python docstring.
Следуй разделу [Comments and Docstrings Google Python Style Guide](https://google.github.io/styleguide/pyguide.html#38-comments-and-docstrings)
и применимым правилам проекта о языке и оформлении. Markdown-правила страниц
не применяй к docstring автоматически.

## Содержание

Начинай с краткого описания назначения. Не пересказывай имя, сигнатуру
и несущественные детали реализации.

Сохраняй сведения, значимые вызывающему коду:

- семантику параметров, единицы, допустимые значения и смысл специальных значений;
- результат, порядок элементов и условия отсутствия результата;
- ограничения, предусловия и значимые исключения;
- побочные эффекты и изменения переданных объектов.

Не добавляй отсутствующие гарантии или исключения по догадке.
Сверяй контракт с реализацией, тестами и нормативными источниками проекта.
При расхождении обозначь его, не меняй код ради согласования текста.

## Разделы

| Раздел | Когда использовать |
| --- | --- |
| `Args` | Чтобы объяснить семантику параметров, которую не раскрывает сигнатура |
| `Returns` | Чтобы описать результат и условия его получения |
| `Yields` | Чтобы описать выдаваемые генератором значения |
| `Raises` | Для исключений, значимых вызывающему коду, с условиями возникновения |
| `Attributes` | Для публичных атрибутов класса, которые требуют пояснения |

Не добавляй пустые разделы или разделы, которые только повторяют аннотации типов.

## Проверка сохранения кода

Если задача ограничена docstring, меняй только их текст. Просмотри полный diff
и сравни AST до и после правки, исключив только docstring модулей, классов и функций.
Сохрани сигнатуры, декораторы, аннотации и остальные строковые литералы.

Сравнение AST подтверждает сохранение исполняемой структуры, но не неизменность
`__doc__` и описаний, которые библиотеки строят из docstring.
Если docstring используется в схемах, инструментах или другом публичном выводе,
проверь соответствующие контракты и не меняй модельное поведение под видом редактуры.
Выполни применимые проверки проекта. Не запускай полный набор тестов автоматически.
