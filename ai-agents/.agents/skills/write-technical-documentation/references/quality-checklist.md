# Чек-лист review технической документации

## Blocking

- [ ] Команды, код, API-контракт и факты соответствуют источнику истины.
- [ ] Основной сценарий исполним в заявленной версии и окружении.
- [ ] Не пропущены обязательные шаги, prerequisites, permissions и зависимости.
- [ ] Warning стоит до опасного или необратимого действия.
- [ ] Нет secrets, персональных данных и внутренних адресов.
- [ ] Есть проверка конечного результата.
- [ ] При существенном риске описаны rollback или escalation condition.

## Цель и полнота

- [ ] Определены читатель, задача и предполагаемый уровень знаний.
- [ ] Выбран один основной тип документа.
- [ ] В начале понятны применимость и ожидаемый результат.
- [ ] Указаны версии, окружение, permissions, ограничения и compatibility.
- [ ] Факты отделены от предположений и рекомендаций.
- [ ] Ссылки действительно подтверждают claims.

## Структура

- [ ] Заголовок точно называет задачу или предмет.
- [ ] По headings можно найти нужный фрагмент.
- [ ] Действия расположены по порядку.
- [ ] Условия и warnings находятся перед зависимыми шагами.
- [ ] Один шаг содержит одно основное действие.
- [ ] Нет пустых sections, лишней вложенности и дублирования.

## Язык

- [ ] Понятно, кто что делает и какой результат ожидается.
- [ ] Нет необоснованных оценок и рекламных усилителей.
- [ ] Один объект называется одним термином.
- [ ] Jargon и сокращения понятны аудитории или расшифрованы.
- [ ] Identifiers, commands и API names не искажены.
- [ ] Текст соответствует style guide.

## Примеры и contracts

- [ ] Команды приведены полностью и в правильном контексте.
- [ ] Ввод и ожидаемый output разделены.
- [ ] Request, response, names и values согласованы.
- [ ] Types, required fields, defaults и constraints подтверждены.
- [ ] Значимые ошибки содержат condition и action.
- [ ] Placeholder нельзя принять за secret.

## Сопровождение

- [ ] Документ проверен владельцем технического контракта.
- [ ] Проверены build, Markdown и links.
- [ ] Изменение документа связано с изменением продукта.
- [ ] Понятно, кто и когда актуализирует документ.
- [ ] Устаревшие версии помечены или архивированы.

## Вердикт

- `Blocking`: не публиковать до исправления.
- `Major`: существенный дефект, не делающий критический путь неверным или
  опасным.
- `Need`: необязательное или косметическое улучшение.

Не повышать severity ради убедительности. Описывать конкретное последствие.
