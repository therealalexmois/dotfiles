# Формат профиля

Профиль владельца – Markdown вне репозиториев, он не должен попадать ни в чей git:

- глобальный: `${XDG_DATA_HOME:-~/.local/share}/team-lead/profile.md`;
- необязательное проектное дополнение: `${XDG_DATA_HOME:-~/.local/share}/team-lead/projects/<repo>.md`.

- `<repo>` – имя каталога основного checkout.
- Из worktree `scripts/profile.py` получает его через `git rev-parse --git-common-dir`: родитель
  общего `.git`, а не имя worktree.
- Вне репозитория используется только глобальный профиль; одинаковые имена checkout используют
  одно дополнение.
- Глобального файла нет – явная ошибка и код 1, даже если есть проектный.
- Исполнителей не запускай, предложи черновик глобального профиля и продолжай после согласования
  владельцем.

- В глобальном – общие параметры владельца: лимит сессий с причиной, модель Codex, пороги квот,
  порог дополнительных задач; общие разделы и блоки только если они действительно общие.
- В проектном – только отличия: основная ветка, заголовок решения issue, worktree, проверки,
  исполнители, ревьюеры, гейты, вливание, подводные камни и блоки задания конкретного проекта.
- Правило проекта профиль не пересказывает, а ссылается на `AGENTS.md` или `CLAUDE.md`.

## Чтение и слияние

```bash
python3 <skill>/scripts/profile.py resolve --repo <checkout-или-worktree>
python3 <skill>/scripts/profile.py show --repo <checkout-или-worktree>
```

`resolve` печатает найденные пути, по одному на строку: глобальный, затем проектный.
`show` печатает объединенный профиль с пометками источника у каждого раздела, ключа параметров
и блока. Оба по умолчанию берут текущий каталог и ничего не записывают.

- Раздел `##` проектного файла целиком заменяет одноименный глобальный.
- `## Параметры` сливаются по ключам, проектное значение побеждает; причина в значении сохраняется.
- Блоки `<!-- team-lead:<имя> -->` сливаются независимо от разделов по имени, проектный побеждает.
  Заголовки `##` внутри блока, например в `report-extra`, не являются разделами профиля.
- Раздел, ключ или блок без пары берется как есть. Порядок глобальных элементов сохраняется,
  новые проектные дописываются; источник смешанного раздела «Параметры» помечается отдельно.

- Разбор и слияние – в `scripts/profile_model.py`, его используют `profile.py` и
  `compose-task.py`.
- Преамбула (заголовок и вводный текст) – из проектного файла, если задана, иначе из
  глобального.
- Профиль без разделов и блоков, неизвестный раздел или блок, дубли в одном файле, пустой блок,
  непарный, вложенный или битый маркер – ошибка.
- Параметры – таблица «Ключ / Значение» из двух колонок; ключи в kebab-case, значения непустые,
  ключи не повторяются.
- Неизвестный ключ сохраняется, но не дает нового поведения скриптам.
- Пустой раздел не означает удаление одноименного блока или ключей.

## Разделы

| Раздел | Содержание | Где используется |
| --- | --- | --- |
| `## Параметры` | таблица ключей ниже | план, квота, запуск |
| `## Worktree` | как создать и убрать worktree; разрешена ли встроенная изоляция агентов | волна |
| `## Проверки` | окружение тестов; когда нужен широкий прогон; полный гейт серии и его окружение; действия после вливания | ревью, вливание, конец серии |
| `## Исполнители` | дополнительные аргументы `codex-launch.sh` и `claude-launch.sh` | запуск |
| `## Ревьюеры` | профильные субагенты и области их diff | ревью |
| `## Гейты` | гейты владельца сверх общих | план, вливание |
| `## Трекер` | необязательный: трекер задач вместо GitHub issues – формат ключа, команды выжимки и деталей, ссылка из PR и значение `--closes`, закрытие и комментарии, что из этого гейт владельца | груминг, волна, issues |
| `## Вливание` | changelog и его правила | вливание |
| `## Подводные камни` | ловушки окружения проекта: хуки, имена команд под правилами разрешений, лимиты размеров | всегда |

## Ключи `## Параметры`

| Ключ | Смысл |
| --- | --- |
| `base-branch` | основная ветка, в которую вливаются PR |
| `max-sessions` | одновременно работающих инженеров в tmux; причина лимита |
| `codex-model` | модель Codex по умолчанию |
| `codex-floor` | остаток недельной квоты Codex (%), ниже которого новые сессии не запускаются; `--quota-floor` его переопределяет |
| `codex-extra-min` | остаток (%) после ядра, при котором берутся дополнительные задачи |
| `claude-floor` | необязательный: остаток окна 7d Claude (%), ниже которого новые агенты Claude не запускаются |
| `issue-solution-heading` | необязательный: заголовок раздела решения в шаблонах issues проекта для `issue-digest.py` |

## Блоки задания

- `scripts/compose-task.py [--repo <путь>]` берет объединенный профиль; `--profile` больше не
  принимается.
- Блоки между маркерами `<!-- team-lead:<имя> -->` и `<!-- /team-lead:<имя> -->` (каждый маркер
  на своей строке) проверяются до слияния, а обязательный `task-context` – после.
- Он может находиться только в проектном файле.
- Во всех блоках подставляются плейсхолдеры `{id}`, `{worktree}`, `{branch}`, `{scratchpad}`;
  прочие фигурные скобки остаются как есть.

| Блок | Обязателен | Куда встает |
| --- | --- | --- |
| `task-context` | да | начало раздела «Контекст»: проект и где его правила |
| `task-criteria` | нет | в конец «Критериев успеха», пунктами |
| `task-constraints` | нет | в конец «Ограничений», пунктами |
| `report-extra` | нет | в конец образца отчета: дополнительные разделы `##`, например предложенная запись changelog |

Общие для всех проектов части задания (git только на чтение, без коммита и PR, без тихих фолбэков, отчет и описание PR, TDD, порядок работы) живут в `assets/task.md` скилла; в блоки профиля их не копируй.
