# Адаптер: Codex в tmux

Исполнитель по умолчанию для реализации issue: долгая автономная работа в своем worktree. У Codex своя недельная квота, и она бережет квоту Claude.

## Запуск

Один шаг – запуск и наблюдатель вместе: сессия без наблюдателя однажды пролежала готовой 17 минут. `<skill>` – абсолютный путь каталога скилла.

1. Окно tmux в сессии Team Lead:
   ```bash
   pane=$(<skill>/scripts/spawn-window.sh cx-<id> <worktree> \
     <skill>/scripts/codex-launch.sh <worktree> <модель> <effort> <scratchpad>/<id>-task.md <доп. аргументы из профиля>)
   ```
   Codex работает с `-a on-request`: вопросы и запросы разрешений приходят в pane.
2. Monitor со скриптом:
   ```bash
   <skill>/scripts/pane-watch.py cx-<id>=<pane>=<scratchpad>/<id>-report.md=<scratchpad>/<id>-pr-body.md=codex [еще сессии...]
   ```
   Monitor живет 30 минут: по истечении запусти заново. Состав сессий изменился – TaskStop и новый Monitor со всеми текущими сессиями.

Аргументы из переменной (например, доп. аргументы профиля) zsh не делит на слова, и запуск молча ломается: пиши их литералом или запускай цикл запусков через `bash -c`. Фоновый `codex exec` годится, только когда вопросов и разрешений заведомо не будет.

Модели Codex перечислены в кэше `~/.codex/models*`; модель по умолчанию – в профиле.

## События наблюдателя

| Событие | Действие |
| --- | --- |
| отчет обновлен | дождись простоя (событие простоя или `pane-watch.py --check-idle <pane>`), затем ревью |
| описание PR записано | часть отчета; то же событие дает и твоя правка этого файла |
| вопрос или запрос разрешения | `tmux capture-pane -p -t <pane>`, ответить (ниже) |
| простой больше 150 с | посмотреть pane: вопрос, готовность или зависание |
| pane закрыт | Codex вышел: проверить отчет и worktree, перезапуск – только после разбора |

## Ответ на вопрос

- Вопрос в UI («? 1 question», «shift+← to answer»): `tmux send-keys -t <pane> S-Left`, затем Enter на варианте. Уточнение к выбору – отдельным сообщением через `tmux-send.sh`.
- Запрос разрешения на команду – решить по ограничениям задания; сомнение – гейт владельца.
- Ответ, который можешь обосновать сам, давай решением с условиями реализации и проверки. Пример для схемы файла: поле аддитивное, версия минорная, старые файлы читаются без ошибки, всех читателей проверить, в отчет – запись о границе сравнимости. Продуктовый вопрос – по разделу «Гейты владельца» SKILL.md.

## Отправка вердикта

`<skill>/scripts/tmux-send.sh <pane> <файл вердикта> codex`: сначала выводит поле ввода из Vim Normal (текст, вставленный в Normal, съедается как команды), затем повторяет Enter, пока Codex не начнет работу – длинный текст приходит вставкой, и первый Enter часто только закрывает ее.

Сообщение во время работы встает в очередь «после следующего вызова инструмента». Прервать сразу – Esc дважды (Insert -> Normal -> прерывание).

Перед вердиктом посмотри строку `Context N% left`: это остаток окна сессии, а не квоты. Ниже примерно 25% – сначала `/compact` в pane, пока Codex не работает (файл с `/compact` через `tmux-send.sh`), затем вердикт.

## Квота и время

`<skill>/scripts/codex-quota.py` – потраченное и остаток недельного окна по журналам `~/.codex/sessions`. Ориентиры из прошлых серий:

| Задачи | Effort | Расход на PR | До отчета |
| --- | --- | --- | --- |
| механика с известным решением, S–M | medium | около 0,5% | 6–17 мин |
| фичи и сложные исправления | high | S около 1%, M около 2%, L 3–5% | 15–25 мин |

Круг правок – 2–5 минут.

## Особенности Codex

- Песочница `workspace-write` пишет только в worktree и в `--add-dir`; часть каталогов она защищает и внутри worktree (какие – в профиле), и хуки pre-commit в ней падают. Поэтому git – у Team Lead, а правки защищенных каталогов Codex описывает в отчете точным текстом.
- Открытый выбор в задании Codex превращает в вопросы в начале работы; где решение за ним – пиши «выбери и обоснуй».
- Codex расширяет объем сам: однажды ввел миграцию схемы, которую не просили. Ловит п. 5 чеклиста ревью.
- Codex пишет в описании PR «владелец подтвердил» про действия Team Lead. Ловит п. 9 чеклиста.
- Размытое поручение Codex понимает как разрешение на догадку: «дай значение там, где строки создаются» стало эвристикой в маппере. Называй, откуда берется значение.
- «Внутренние» сигнатуры рендера Codex принимает за публичный API и спрашивает о них – отвечай сразу.
