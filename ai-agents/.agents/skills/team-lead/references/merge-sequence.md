# Вливание PR

Выполняет Team Lead, шаги строго по порядку: каждый защищает от сбоя, который уже случался. Команды – в bash с `set -o pipefail`; вывод длинных команд пиши в файл и читай хвост. В цепочке `pytest ... | tail && git commit` без `pipefail` упавший тест не останавливает коммит.

1. **Устойчивый простой.** Tmux: `scripts/pane-watch.py --check-idle <pane> --kind <codex|claude>` вернул 0 – нет признака работы в двух замерах с паузой. Одиночный снимок врет: строка приглашения мелькает и между шагами, и инженер дважды дописывал тест во время коммита. Субагент: пришло уведомление о завершении.
2. **Правки вне песочницы.** Внеси точный текст из отчета инженера (например, файлы, защищенные песочницей).
3. **Коммит.** `git -C <wt> add <файлы по списку из status>`, commit с заголовком из первой строки отчета. Хуки pre-commit, которые переписывают файлы, оставляют дерево измененным: просмотри diff, добавь и закоммить снова.
4. **Слияние с основной веткой.** `git -C <wt> fetch origin && git -C <wt> merge origin/<base>`; конфликты разрешаешь сам (исключение роли). После слияния – адресные тесты по правилам проекта.
5. **Changelog** (если он есть в профиле): запись по правилам профиля с меткой `(#PR<id>)` вместо номера; commit.
6. **Push.** `git -C <wt> push -u origin <branch>`. Отказ – стоп и отчет владельцу, защиту удаленного репозитория не обходить.
7. **Описание PR.** Возьми `<id>-pr-body.md` инженера, убери устаревшее, допиши строку о своих проверках после слияния (ревизия, команды, результаты).
8. **Открытие PR и номер.** Номер подставляй, только если он непустой – сетевой обрыв `gh` однажды записал `(#)`:
   ```bash
   url=$(gh pr create --base <base> --head <branch> --title "<заголовок>" --body-file <файл>) \
     && n=${url##*/} && [ -n "$n" ]
   ```
   Замени метку `(#PR<id>)` на `(#$n)`, commit, push.
9. **Вливание.** `gh pr merge <n> --squash --match-head-commit "$(git -C <wt> rev-parse HEAD)"`. При сетевом сбое сначала `gh pr view <n> --json state`: повторяй, только если PR еще не MERGED.
10. **Уборка** – в этом порядке: git не удаляет ветку, пока она выгружена в worktree.
    1. `tmux kill-window -t <pane>` для сессии в tmux: процесс инженера не должен держать каталог.
    2. `sha=$(git rev-parse <branch>)`, затем `git worktree remove <wt>` без `--force`: отказ на грязном дереве означает, что что-то не сохранено – разберись. Затем `git worktree prune`.
    3. Ветка: `gh pr view <n> --json state,headRefOid` показал MERGED и `headRefOid` равен `$sha` – тогда `git branch -D <branch>`; назови удаленный SHA.
    4. Основной checkout: `git pull --ff-only`.
11. **После вливания.** Действия из профиля (синхронизация зеркал, миграция данных после гейта владельца); миграцию проверь повторным запуском.
12. **Состояние.** Строка в «Влито» файла состояния и следующий шаг.

Чужие worktree и ветки не трогай, даже если они выглядят брошенными: упомяни их в отчете владельцу.
