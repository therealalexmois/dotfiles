# Чек-лист технического маркетингового контента

## Точность и доказательства

- [ ] Technical claims подтверждены первичными источниками.
- [ ] Числа содержат source, period, scope и baseline, если он нужен.
- [ ] Quotes и customer outcomes подтверждены.
- [ ] Факты отделены от interpretation и recommendation.
- [ ] Ограничения не скрыты ради более сильного обещания.
- [ ] Нет выдуманных integrations, benchmarks и roadmap commitments.

## Цель и аудитория

- [ ] Определены бизнес-цель, аудитория и одно основное действие.
- [ ] Понятны проблема, текущая альтернатива и decision criteria читателя.
- [ ] Формат соответствует этапу воронки и каналу.
- [ ] Материал дает самостоятельную пользу, а не только перечисляет features.

## Ценность и структура

- [ ] Заголовок содержит конкретное и подтверждаемое обещание.
- [ ] Механизм продукта связан с наблюдаемым изменением.
- [ ] Proof расположен рядом с claim.
- [ ] Основной вывод находится до второстепенного контекста.
- [ ] CTA соответствует готовности читателя и объясняет следующий шаг.
- [ ] Нет конкурирующих CTA.

## Язык

- [ ] Нет канцелярита, пустых усилителей и кликбейта.
- [ ] `Лучший`, `быстрый`, `надежный` и подобные оценки доказаны или удалены.
- [ ] Jargon соответствует уровню аудитории.
- [ ] Один объект называется одним термином.
- [ ] Текст можно понять без скрытого product context.

## SEO, если входит в задачу

- [ ] Определен search intent.
- [ ] Title, H1, headings и description соответствуют содержанию.
- [ ] Нет keyword stuffing и искусственных FAQ.
- [ ] Internal links продолжают задачу читателя.
- [ ] External links ведут на актуальные первичные источники.
- [ ] SEO не искажает technical terminology.

## Границы

- [ ] Материал не подменяет documentation там, где нужны точные шаги или contract.
- [ ] Product announcement отделен от migration guide и release notes.
- [ ] Comparison использует одинаковые criteria и актуальные sources.
- [ ] Case study не расширяет результат одного клиента на всех пользователей.

## Вердикт

Сначала перечислить проблемы, которые меняют точность, аудиторию, promise или
CTA. Затем дать краткий вывод о готовности. Не придумывать findings для полноты
списка и не переписывать материал без запроса.
