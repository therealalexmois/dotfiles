# Проверка поведения skill

Не загружай этот файл при написании самооценки. Используй при изменении skill.

## Прогоны

1. Возьми prompt и files из `evals/evals.json`. Не показывай исполнителю
   expected_output, assertions, эталонные ответы и выводы предыдущих итераций.
2. Для каждого кейса создай два свежих контекста: со skill и без него. Передай
   одинаковые задачу, исходные данные и возможности; только первому дай путь
   skill. Не допускай чтения этим запуском evals и ответов других запусков.
3. Используй одну модель и effort. Укажи ограничения изоляции: общие системные
   инструкции и прочие skills могут оставаться доступными. Это не чистый API A/B.
4. Сохрани ответы отдельно от skill, в workspace с `iteration-N`, ID кейса и
   `with_skill` или `without_skill`. Сохрани доступные traces и wall time;
   неизвестные token counts оставь null. Не выдумывай измерения.
5. Первую итерацию оцени по expected_output; после просмотра зафиксируй
   конкретные assertions. Проверь структуру программно, фактическую точность
   и покрытие смысловых пунктов по исходникам. Для каждого PASS или FAIL приведи
   цитату либо проверяемую ссылку на результат. По возможности скрой от judge
   принадлежность ответов к конфигурации.
6. Покажи сырые количества пройденных проверок и провалов по кейсам. Отдельно
   проверь критические нарушения: выдумка, присвоение, выход за период,
   утечка, нарушение запрета на финал. Их нельзя скрыть высоким средним баллом.
7. Отдели объективные проверки от оценки читабельности и убедительности.
   Человеческая проверка стиля остается отдельной; не называй model review
   пользовательским одобрением. Один прогон не доказывает устойчивое улучшение.
8. Исправляй общую причину провала, а не добавляй ответ конкретного кейса в
   инструкции. Повтори затронутые кейсы в свежих контекстах и добавь другой
   сценарий для проверки переноса. Не ослабляй assertions ради прохода.

Общие для обеих конфигураций успешные safety-checks сохраняй как регрессионные,
но не выдавай их за доказательство дополнительной ценности skill.

## Источники проектирования

- https://agentskills.io/specification
- https://agentskills.io/skill-creation/best-practices
- https://agentskills.io/skill-creation/evaluating-skills

Skill использует компактное ядро, загрузку ресурсов по задаче и сравнение
результатов в свежих контекстах. Конкретные правила отбора достижений извлечены
из реальной сессии подготовки самооценки; они не являются требованиями стандарта.
