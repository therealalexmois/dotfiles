# Чем заменить `tessl review` - исследование

**Статус:** исследование, решение не принято. Код не пишется по итогам этого документа.

**Проблема:** лимит Free plan в tessl исчерпан (1000 кредитов, `tessl org usage` показывает
"limit exceeded"). `tessl skill lint` работает локально и бесплатно, `tessl review run quality` -
нет. Нужно понять, чем реально закрывается потеря.

**Требования (подтверждены):** нужны обе половины, но раздельно - дешевая детерминированная
проверка на каждый прогон и LLM-судья точечно. Инструмент - свой, на Python, в этом репозитории.
Раннер LLM должен подключаться разный, без привязки к Claude, но с возможностью гонять через
`claude`.

## 1. Что такое `tessl review` внутри

Разложено по сохраненным JSON-отчетам (31 first-party скилл, `scratchpad/reviews/`).
Итоговый балл - взвешенная сумма трех компонентов:

| Компонент | Вес | Что это |
| --- | --- | --- |
| `validation` | 0.2 | 16 детерминированных проверок |
| `description` | 0.4 | LLM-судья, 4 критерия по шкале 1-5 |
| `content` | 0.4 | LLM-судья, 4 критерия по шкале 1-5 |

**Детерминированные проверки (16):** `skill_md_line_count` (<= 500), `frontmatter_valid`,
`name_field`, `description_field` (<= 1024), `compatibility_field` (<= 500), `allowed_tools_field`,
`metadata_version`, `metadata_field`, `license_field`, `frontmatter_unknown_keys`, `body_present`,
`scripts_directory`, `references_directory`, `assets_directory`, `relative_links`,
`referenced_paths_exist`.

Две последние - самые полезные и самые неочевидные: `relative_links` резолвит ссылки **только
внутри** `references/`, `scripts/`, `assets/`; `referenced_paths_exist` ловит упоминания путей в
тексте, даже не оформленные ссылкой, и отдельно отмечает вложенность глубже одного уровня.

**Судья `description` (вес 0.4):** `specificity`, `completeness`, `trigger_term_quality`,
`distinctiveness_conflict_risk`.

**Судья `content` (вес 0.4):** `conciseness`, `actionability`, `workflow_clarity`,
`progressive_disclosure`.

Каждый критерий - оценка 1-5 с текстовым обоснованием, плюс список `suggestions` и
`overall_assessment`. В обоснованиях видны **якоря шкалы**: "matches the 'names domain and 1-2
concrete actions' anchor and falls short of the 'several specific actions' anchor above". То есть
рубрика задана не абстрактно, а описанием каждого уровня - это и делает оценки стабильными.
Воспроизвести рубрику по обоснованиям реально; у нас есть 31 отчет как образцы.

**Вывод:** 80% ценности tessl - в двух LLM-судьях, а не в валидации. Валидацию мы уже почти
целиком повторили в `scripts/check-skills.sh` и разовых проверках.

### skill-validator - что именно брать

Единственный из пяти, кто делает обе половины. Проверки статики шире tessl:

- токены по `o200k_base`, отдельно по файлам и суммарно (SKILL.md > 5000 токенов - warning;
  reference > 10000 - warning, > 25000 - error; сумма references > 50000 - error);
- orphan-файлы: лежит в бандле, но ни из чего не достижим;
- незакрытые code fence;
- внешние ссылки HEAD-запросом (403 не считается ошибкой - многие сайты режут ботов);
- **contamination** = 0.3 * multi_interface + 0.4 * language_mismatch + 0.3 * scope_breadth,
  то есть «скилл про всё сразу» ловится числом;
- content-метрики: доля кодовых блоков, доля императивных предложений, information density,
  instruction specificity = strong_markers / (strong + weak).

Его LLM-судья: 6 измерений для SKILL.md (clarity, actionability, token efficiency, scope
discipline, directive precision, novelty) и 5 для reference-файлов (clarity, instructional value,
token efficiency, novelty, skill relevance). Провайдеры: `anthropic`, `openai`,
**`claude-cli`** (шеллит в локальный `claude`, ключ не нужен), плюс `--base-url` на любой
OpenAI-совместимый endpoint. Кэш результатов в `.score_cache/` по ключу провайдер+модель+файл.

Честная оговорка из его же README: провайдер `claude-cli` подтягивает локальный контекст
(CLAUDE.md, память проекта, правила), поэтому оценки хуже воспроизводятся между машинами.

### Чего нет ни у кого

**Судьи по `description` как отдельному артефакту.** skill-validator судит SKILL.md целиком;
tessl выделяет описание в отдельный компонент с весом 0.4 и четырьмя критериями, включая
`distinctiveness_conflict_risk` - риск конфликта с другими скиллами. Для набора из 135 скиллов
это самый ценный критерий: именно описание решает, сработает ли скилл и не перехватит ли
чужой запрос. Ни один OSS-кандидат этого не делает - писать самим.

## 3. Брейншторм раннеров LLM

Требование: разные раннеры за одним интерфейсом, переиспользуемость на работе, возможность
гонять через `claude`.

**A. `claude -p` (print mode).** Проверено: `claude -p --output-format json 'prompt'` возвращает
JSON с полями `result`, `usage`, `total_cost_usd`, `session_id`. Плюсы: на подписке, ключ не
нужен, сильная модель. Минусы: тянет локальный контекст (CLAUDE.md, правила) - лечится флагами
изоляции; холодный старт ~2 с на вызов плюс кеш-прогрев (в тесте 47k токенов кеша на пустой
запрос); на работе может быть недоступен.

**B. Anthropic API напрямую.** Плюсы: воспроизводимо, temperature=0, structured output через
tool use. Минусы: платный ключ - ровно та проблема, из-за которой все и началось.

**C. OpenAI-совместимый HTTP.** Один транспорт закрывает Ollama (`http://localhost:11434/v1`),
vLLM, LM Studio, корпоративный прокси. **Главный кандидат для работы:** в этом репозитории уже
живут `NVIM_AI_WORK_URL` / `NVIM_AI_WORK_API_KEY` / `NVIM_AI_WORK_MODEL` для CodeCompanion -
тот же endpoint переиспользуется судьей без новой инфраструктуры.

**D. Локальная модель через Ollama.** `ollama` установлен. Плюсы: бесплатно, офлайн,
воспроизводимо при фиксированном seed. Минусы: качество суждений заметно ниже; для рубрик с
якорями 1-5 маленькая модель плывет. Годится как smoke-раннер в CI, не как арбитр.

**E. `codex exec`.** Тот же класс, что A, но через другую подписку. Полезен как второй
независимый судья, если захочется консенсуса двух моделей.

**F. LiteLLM как универсальный адаптер.** Один Python-пакет вместо своих HTTP-клиентов, ~100
провайдеров. Плюс: не писать транспорт самому. Минус: тяжелая зависимость и чужие абстракции
там, где своих нужно две-три; противоречит цели «разобраться в архитектуре».

**Рекомендация:** свои раннеры A + C, где C покрывает и Ollama, и работу. B - опционально,
если появится ключ. F - сознательно не брать: ради двух транспортов зависимость не окупается.

## 4. Архитектура Python-инструмента - эскиз

Три слоя, каждый работает без следующего:

```
skillcheck/
├── rules/        детерминированные проверки -> список Finding
├── judge/        рубрики + раннеры -> список Score
└── report/       объединение, веса, вывод (text | json | markdown)
```

**Слой правил.** Чистые функции `(SkillBundle) -> list[Finding]`, без сети и LLM. Сюда - все 16
проверок tessl плюс то, что мы уже написали руками: валидный YAML frontmatter (наш реальный
источник 13 поломок), резолвинг ссылок только внутри bundle-каталогов, глубина ссылок, токены.

**Слой судьи.** Интерфейс раннера - один протокол:

```python
class JudgeRunner(Protocol):
    name: str
    def complete(self, prompt: str, *, schema: dict[str, Any]) -> dict[str, Any]: ...
```

Реализации: `ClaudeCliRunner` (subprocess + `--output-format json`), `OpenAICompatRunner`
(httpx, base_url + model из env), при желании `AnthropicRunner`. Рубрика - данные, не код:
YAML с критериями и текстовыми якорями для каждого уровня 1-5, отдельно для `description` и для
`content`. Тогда рубрику правят без правки кода, а на работе подменяют своей.

**Воспроизводимость и деньги.** Кэш по хешу (содержимое файла + рубрика + модель + версия
промпта) - как `.score_cache` у skill-validator. Без кэша повторный прогон 135 скиллов
бессмысленно дорог по времени.

**Калибровка.** У нас есть 31 отчет tessl с оценками и обоснованиями. Это готовый размеченный
набор: прогнать свой судья на тех же скиллах и посчитать корреляцию с tessl. Пока эти отчеты
лежат в scratchpad - их стоит сохранить в репозиторий, иначе калибровать будет не по чему.

## 5. Что реально заменяется, а что нет

**Заменяется полностью:** вся детерминированная часть. Более того, наш чекер уже ловит то, чего
tessl lint не ловит без манифеста плагина, а skill-validator добавляет токены, orphans и
contamination.

**Заменяется с оговоркой:** LLM-судья. Рубрики воспроизводимы, модель у нас есть. Но абсолютные
числа не будут сопоставимы с историей tessl - другой промпт, другая модель. Сравнивать можно
только внутри своей шкалы, начиная с новой точки отсчета.

**Не заменяется:** внешний независимый арбитр. tessl судит чужой моделью по чужой рубрике, и в
этом была часть ценности - он ловил то, на что у автора замылен глаз. Свой судья на своей
рубрике наследует слепые пятна автора рубрики. Частично лечится вторым раннером другой модели
(вариант E) и требованием цитировать конкретное место в тексте для каждого замечания.

## 6. Следующий шаг

Сузить до одного вопроса: делаем ли слой судьи сразу или сначала только слой правил. Слой правил
- день работы и полностью закрывает CI. Слой судьи - интереснее, но именно он требует рубрик,
кэша и калибровки.
