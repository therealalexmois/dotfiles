# Tier 1 Rules Engine - дизайн

**Статус:** дизайн-спека к утверждению. Реализация и разбивка на задачи - следующим шагом.

**Цель:** превратить `lint_banned_terms.py` из линтера одного типа правил в общий
детерминированный gate для skill `writing` - страховочный слой против механических
промахов, которые LLM пропускает (случайный `—`, `ё`, двойной пробел, запрещенная
основа).

**Не-цель:** оценка читаемости баллом (как Главред). Контекстно-зависимое остается
у LLM (Tier 2). Причина - в решении 6.

---

## Решение 1. Планка допуска в Tier 1

Правило попадает в Tier 1 тогда и только тогда, когда выполнены все три условия:

1. **Контекстная независимость.** Конструкция неверна практически в 100% контекстов
   прозы; вердикт не требует понимания смысла, жанра и авторства.
2. **Перечислимые исключения.** Любое легитимное исключение выписывается конечным
   списком (carve-out), а не формулируется как «зависит от намерения автора».
3. **Механическая проверяемость.** Ревьюер подтверждает вердикт, глядя на сам токен,
   а не на абзац.

Если правилу нужно «смотря что имелось в виду» - это Tier 2 (LLM), не Tier 1. Планка
существует, чтобы слой не оброс нечеткими проверками и не потерял свою единственную
ценность - ноль ложных срабатываний.

## Решение 2. Каталог правил

Стартовый набор (узкий и защитимый):

| ID | Правило | Tier 1 | fixable | Scope-нюанс |
| --- | --- | --- | --- | --- |
| R1 | Запрещенные основы (провижинг) | да, готово | нет (замену выбирает человек) | стандартная маска |
| R2 | `—` U+2014 при политике «только `–`» | да | да (`—` -> `–`) | только проза |
| R3 | `ё` при политике «писать `е`» | да | да, автозамена `ё`->`е` | опциональный список исключений в TOML (пусто по умолчанию) |
| R4 | Двойные пробелы, пробел перед `,.;:` | да | да | carve-out: markdown-перенос (2 пробела в конце строки) и строки таблиц (выравнивание ячеек) |

Канцелярит общего вида (`является`, `осуществляется`) в Tier 1 **не входит** -
контекстно-зависим, остается в Tier 2. Фиксированные канцелярские фразы добавляем в
Tier 1 только если конкретная фраза докажет 100% некорректность; по умолчанию - нет.

## Решение 3. Конфиг vs код

- **Типы правил - в коде.** Каждое правило - маленький матчер за общим протоколом.
- **Данные, которые меняются, - в TOML.** Список терминов (`banned-terms.toml`) и,
  при необходимости, списки исключений. Логику правил в TOML не выносим - конфиг не
  должен становиться мини-языком.
- Реестр правил в коде; движок прогоняет все включенные правила по каждой строке.

Протокол правила (эскиз):

```python
class Rule(Protocol):
    id: str
    fixable: bool

    def find(self, masked: str, raw: str, lineno: int) -> Iterable[Finding]: ...
    def fix(self, raw: str) -> str: ...  # только если fixable
```

`masked` - строка с вырезанными кодом/URL (длина сохранена, офсеты совпадают с raw);
`raw` - исходная строка для правил, которым нужен реальный контекст (R4) и для автофикса.

## Решение 4. Маскирование и исключения на правило

Общая инфраструктура маскирования (уже есть): пропускаются code fences, indented code,
HTML-блоки, frontmatter, inline-код, URL. Поверх нее:

- R1, R2, R3 - стандартная маска.
- R4 - стандартная маска плюс собственные исключения: **не флагать два пробела в конце
  строки** (markdown hard line break) и **пропускать строки таблиц** (пробелы там
  выравнивают ячейки, а не засоряют прозу). Строки таблиц берутся из `table_open`
  токенов markdown-it; исключение локальное для R4 - длинное тире и запрещенные основы
  в ячейках ловят другие правила. Правило смотрит только на внутристрочные прогоны и
  пробел перед пунктуацией.

Вывод дизайна: маска - общий препроцессинг, но правило вправе доопределить свои
carve-out на `raw`.

## Решение 5. Политика автофикса

- **Автофикс на raw по офсетам матча.** Маска сохраняет длину, поэтому `start/end` из
  `masked` один-к-одному ложатся на `raw`: `raw[:start] + repl + raw[end:]`. Правки
  идемпотентны и не касаются кода/URL.
- **fixable:** R2 (`—`->`–`), R4 (схлопнуть двойной пробел, убрать пробел перед
  пунктуацией).
- **report-only:** R1 (термин требует выбора замены).
- **Режим `--fix`:** применяет только fixable-правила, report-only оставляет как
  findings. Exit 0, если после фикса не осталось report-only; иначе 1.

**R3 (`ё`) - решено: fixable.** Автозамена `ё`->`е` по политике «всегда `е`». Известный
риск: замена не всегда сохраняет смысл (`всё`->`все`, `узнаём`->`узнаем`), а ловит линтер
чаще вставленный/чужой текст, где различие критично. Митигация - **опциональный список
исключений `yo_keep` в TOML** (пустой по умолчанию): слова из него детектируются, но не
автозаменяются, разрешает человек. Политику «всегда `е`» не нарушает, дает escape hatch
под конкретные семантические коллизии.

## Решение 6. Контракт Tier 1 / Tier 2

- Tier 1 (скрипт) отрабатывает детерминированно, его вердикт **авторитетен и не
  обсуждается**. Планка (решение 1) гарантирует, что Tier 1 не выдаст правило, которое
  LLM был бы вправе переопределить.
- Tier 2 (LLM в skill) берет все контекстно-зависимое: читаемость, канцелярит, ритм,
  авторство.
- Порядок в edit-режиме: LLM делает свой проход -> Tier 1 прогоняется как механический
  страховочный слой -> `--fix` чинит fixable, report-only человек/LLM разрешает.
- `SKILL.md` уже зовет линтер; расширяем инструкцию до «после правки прогони, применяй
  `--fix`, разрули report-only».

## Что меняется в коде (обзор, не задачи)

- Ввести `Rule`-протокол и реестр; текущий матчер терминов переоформить как `R1`.
- Добавить `R2`, `R4` (и `R3` в режиме по итогу форка).
- Движок: на каждую строку прогнать все правила; собрать findings; в `--fix` применить
  fixable на raw.
- Коды выхода: 0 чисто, 1 остались report-only/findings, 2 ошибка конфига/чтения.

## Ревизия после red-team (2026-07-16)

Red-team прогон (24 атаки) подтвердил ядро и сломал инфраструктуру вокруг него.
Принятые контрактные уточнения:

- Маскирование inline-кода - по CommonMark: backtick-run парятся по равной длине,
  экранированный backtick не открывает спан, спан может пересекать перенос строки
  внутри абзаца (блок непустых, не исключенных строк).
- Inline-маски сужены: autolink/HTML-тег требует `<` + значимый первый символ;
  URL - только printable ASCII; target ссылки с одним уровнем вложенных скобок;
  строки reference definitions (`[id]: ...`) маскируются.
- `--fix` сохраняет представление файла: EOL построчно (`\n`/`\r\n`/`\r`), BOM,
  отсутствие завершающего перевода строки; U+2028/U+2029/`\f`/`\v` не считаются
  переводами строк. Правки повторяются до неподвижной точки (кап 10 проходов).
- Carve-out R4 расширен: выравнивание после маркера списка (`-   пункт`, MD030).
- Frontmatter закрывается только до первой пустой строки; документ, начинающийся
  с thematic break `---`, не считается frontmatter.
- Exit 2 усилен: явно переданный не-markdown файл - ошибка вызова; `[term]`
  вместо `[[term]]` и пустой `patterns` - ошибки конфигурации.
- Findings сортируются по `(line, col)`.

## Ревизия после red-team раунд 2 (2026-07-16)

Раунд 2 (24 атаки) подтвердил, что все 14 находок раунда 1 закрыты, и вскрыл 12
новых - все в одном корне: линтер строил параллельную regex-модель Markdown вместо
использования токенов markdown-it. Смена подхода:

- **Сегментация по inline-токенам.** Backtick-спаны считаются внутри диапазона
  одного inline-токена markdown-it (абзац, заголовок, ячейка, пункт списка), а не
  по эвристике «непустые строки подряд». Чужой backtick из соседнего блока не
  спаривается через границу. Закрывает false-negative в заголовке, списке и ячейке
  таблицы (round-2 #2, #3).
- **Единый источник backtick-спанов.** `prose_spans` больше не считает inline-код;
  он приходит только из `code_span_lines` по segment-ам. Убрана двойная модель,
  которая расходилась (round-2 #4, #8).
- **Frontmatter - плагином markdown-it**, а не ручной эвристикой. Авторитетно
  разбирает YAML с пустой строкой внутри (round-2 #7) и согласуется с Obsidian:
  ведущий `---...---` - всегда frontmatter (переопределяет пуристский вывод
  round-1 #4).
- **URL тянется до пробела** (`https?://\S+`): кириллические IRI маскируются
  целиком (round-2 #1, #5). Принятый компромисс: тире, приклеенное к URL без
  пробела, считается частью адреса (round-1 #12).
- **REF_DEF по полной грамматике** reference definition (destination + optional
  title + конец строки): глоссарная проза «[термин]: описание» больше не
  маскируется (round-2 #6), а настоящий refdef маскируется целиком, включая title
  (round-2 #10).
- **Данные:** `(за)?диспетч(?!ер)` ловит «задиспетчить» (round-2 #12).

**Осознанно приняты как пределы** (экзотика, нереалистичный вход для целевых
текстов; гнаться за асимптотической CommonMark-точностью здесь - over-engineering):

- невалидный inline-тег с пробелами `<b и слово>c` маскирует прозу (round-2 #9);
- link target с двойной вложенностью скобок правится (round-2 #11);
- backslash-escape backtick внутри уже открытого code span (round-2 #8).

## Принятые решения

1. **R3 (`ё`): fixable** с опциональным списком исключений `yo_keep` в TOML.
2. **Первая реализация:** рефактор в `Rule`-протокол (переоформить R1) + R2 + R4 + режим
   `--fix`. R3 - fast-follow следующей итерацией.
